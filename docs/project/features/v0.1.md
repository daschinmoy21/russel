Snapshot as of **2026-09-28**. The live checklist is the release tracker, [#56](https://github.com/daschinmoy21/russel/issues/56).

## Scope

v0.1 is a single-host deployer for **one trusted operator**. **Containers (rootless Podman)** are the default runtime. **MicroVMs (Cloud Hypervisor)** ship as **experimental but working**: they accept the same Russelfile fields as containers and run under the same unprivileged ctrl. v0.1 is not multi-tenant, has no agent sandboxes, and runs on one node only.

A v0.1 blocker is something broken on the container path, or something that would break users if it changed after release.

## Verified on 2026-09-28

- `cargo fmt`, `clippy -D warnings`, and the whole workspace test suite pass on `main`.
- CI deploys every container example against a non-root ctrl and probes each app.
- A local sweep (`RUNTIME=microvm contrib/tests/deploy_examples.sh`, non-root ctrl, KVM) passed **13/13 examples as microVMs** on the merged stack: basic-http, caddy, env-config, filebrowser, hello-rust, meilisearch, microvm-http, navidrome, postgres, redis, shortlink, static-test, vaultwarden.

## Known gaps (not blocking)

- **#69**: containers reject an entrypoint that is a relative symlink (busybox applets, `python3 -> python3.x`).
- **#70**: service ids shaped like a generation (`<id>_g<hex>`) are accepted, and the ownership checks can confuse them with `<id>`.
- **Dirty generations**: `update`, `rollback`, and health restart of a generation deployed from a tree with uncommitted changes build whatever the source holds now, not the recorded commit. That commit may not contain the Russelfile.
- **Old Podman**: secrets use `podman secret create` without `--replace`, so Podman 4.3 (Debian 12) works.
- Code-quality and scaling follow-ups (#31–#37, #48–#51, #57, #58) are tracked but out of scope for v0.1.

## After v0.1

The order is v0.1 → agent sandboxes → v0.2.

- **Agent sandboxes next** (epic #71): microVM first, with gVisor or PVM for hosts without KVM. This needs a full Linux guest (`guest = "linux"`, #24, #26, #27).
- **Then v0.2, production readiness** (tracker #83): replicas and autoscaling on one host (#25, #29, #30), and desired run state, so enabled services come back after a reboot (#60).
- Destroy that follows `[[volumes]].keep` (#59) is tracked but not yet assigned to a release.
